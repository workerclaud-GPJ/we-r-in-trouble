# Changes 25 Oct 2026: RouteTopple + item system

Everything in this file is **already in the open Studio session** (Hamster Conquror The World, placeId 103813855206138). The place has **not been saved**. Save it in Studio, then copy these files into the Rojo project so that the next `rojo serve` sync does not overwrite or delete them.

Each file's path here is its Roblox instance path. For example, `ServerScriptService/Server/Services/ItemService.lua` is `game.ServerScriptService.Server.Services.ItemService`. Put each file at the matching place in your Rojo `src` tree.

## Switches (`ReplicatedStorage.Shared.Config.Features`)

| Switch | Does | Tested in Studio (solo) |
|---|---|---|
| `RouteTopple` | The IroningBoard and BreadBoard topple during an Earthquake and become new ramps | Pass |
| `ItemPhysics` | Lying items are physics objects owned by the server; the earthquake knocks them around | Pass |
| `CapabilitySpawn` | Each round places 8 items from a seed, with every required item type guaranteed to appear | Pass |
| `NewMission` | Deliver accepts any item with the Power capability (Battery or ChargerCable) | Spawn path pass (delivery by hand not tested) |

All switches are committed as `false`. To ship a feature, set its switch to `true`. With every switch `false`, a full round plays exactly as before. I tested this: one anchored battery, the RouteTopple pieces are removed from the map, and there are no new errors.

## Test results (Studio solo, 25 Oct ~03:00)

- **Loot:** `lootcheck 1000` shows 1000 seeds, 12 spawn points, **failed=0**, fallback never needed.
- **Physics items:** 8 items spawn per round with `Anchored=false`, CollisionGroup `Items`, and the server as network owner. During Earthquake Active, items are kicked around and none are lost.
- **RouteTopple:**
  - Both boards were scheduled automatically 12 s and 19 s into Active, wobbled during the warning, and landed.
  - Each landing pivot was within 0.001 studs of the authored pose.
  - The landed boards measure as designed: IroningBoard runs from floor (125.5, 0.05, 97.9) to counter (125.5, 45, 30) at 33.5°. BreadBoard runs from counter (120.5, 45.05, 26.5) to sill (104.7, 61, 10) at 34.9°.
- **Walk test:** `Humanoid:MoveTo` reached the top of both ramps (floor to counter in 6.7 s, counter to sill in 2.4 s).
- **Flood rounds:** nothing topples (`TopplesOn = "Earthquake"`).
- **Console:** no errors from game code across 3 rounds.
- **Not tested yet:** 4 real players, frame rate on an old phone, and delivering items by hand.

## Security: backdoor scripts found and quarantined

Fourteen scripts in `Workspace.Lobby` and `Workspace.Terrain` called `require(3667797501)`, `require(3664252382)` or `require(6192017683)`. Their names were `Debounce`, `Welding`, `Fix`, `Script`, and one name that is just a space. I disabled them and moved them to `ServerStorage._Quarantine_Backdoor`; they were not deleted.

During play tests, scripts like these still get injected into the character at runtime: `FallDamage`, `...NeckBallSocket.Welding`, `...BodyPartDescription.Fix`, and `cloud_142678967.Macy.HealthScript`. That points to an infected plugin or inserted model that is still active. Remove unknown plugins before publishing, then delete the quarantine folder and save.
